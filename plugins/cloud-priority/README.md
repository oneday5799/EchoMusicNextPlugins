# 云盘优先

正式插件，参考 EchoMusicPlugins/cloud-priority。播放曲库歌曲时，如果当前账号的音乐云盘存在同一首歌，自动把当前播放切换到云盘文件；宿主没有匹配到云盘文件时保持原音源。

- 只使用公开 SDK：`ctx.player.snapshot` 观察当前曲目与音源，`ctx.player.control('quality', { value: 'cloud' })` 复用宿主“云盘文件”音源切换。
- 不读取宿主内部状态、云盘索引、播放器实现或账号数据，不直接请求云盘网络接口，不需要额外 capability。
- 宿主在解析曲目时加载云盘索引；索引尚未就绪时切换请求不会生效。曲库源解析完成并打开后，首次切换等待约 500ms 稳定窗口再发出——宿主的 `loading` 只在引擎打开音源时清除，此刻 `playing` 尚未上报，立即切换会走非无缝重载路径；等待后切换与手动切换走同一条无缝换源路径。
- 未生效的切换按 700ms/1.5s/3s/6s 退避重试；重试只由定时器链驱动，播放器事件不会叠加切换。
- 每首曲目只有一轮云盘尝试：切换已实际触发重载后（无论成功或宿主回退）即停止，不与宿主争抢。若结尾回到曲库音质（例如 SD），表示宿主在云盘取址或云盘流播放失败后按设计回退，并从默认音质向下兼容到可用音质；插件不会再次切换——那会把一次可恢复的回退放大成“解码失败，跳过曲目”的终止失败。
- 已经由云盘、本地文件、MV 或其它插件提供的音源不处理。
- 停止插件不打断当前正在播放的音频，只停止后续曲目的自动切换。

命令（管理页/`executeCommand` 可用）：`apply` 立即尝试一次并返回当前 `sourceKind`；`status` 返回 `sourceKind`、`noticeCode` 与 `errorMessage`，用于定位云盘源失败原因。

构建：仓库根执行 `npm run build`；生成 `dist/cloud-priority-1.0.2.echomod`。通过插件管理面板安装，或使用 `--plugin-dir` 加载构建目录。SDK 保持 1.0.0，插件版本 1.0.2。图标与原始逻辑沿用旧插件的 MIT 许可，见 `LICENSE`。
